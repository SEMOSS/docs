# Create Diabetes Record

This example is designed to show you how a simple, form-based application can come to life in SEMOSS, without writing a single line of full-stack code.  

With just drag-and-drop blocks, reusable variables, and a notebook that knows how to talk to your database, you’ll see how to transform a handful of input fields into a working data entry app.  

Think of this template as a guided experiment:  
- You enter patient details like *Age*, *Glucose*, or *Blood Pressure*.  
- SEMOSS captures those values as variables and prepares an SQL insert statement.  
- A single button click runs the notebook, inserts the record into the database, and shows you a response.  

---

## Why this template matters

Every data-driven app begins with a simple flow: **collecting inputs → storing them reliably**.  
This template walks you through that journey step-by-step. By exploring it, you’ll discover:  

- How UI blocks map directly to variables.  
- How variables feed into a query that inserts new rows.  
- How button actions and response handling make the experience seamless.  

---

## Prerequisites

Before exploring this guide in detail, we recommend that you first review the foundational topics listed below.  
→ [Review the Variables Guide](/docs/building-apps/app-templates/variables-guide) to revise these topics:

- **Blocks & Input Fields**  
  Blocks are the building units of your app viz. text fields, dropdowns, buttons, charts, and more.  
  For this template, you’ll mostly use **input fields** (for patient data) and a **button** (to trigger the insert).  
 

- **Variables**  
  Variables capture the values from your blocks and make them reusable inside queries and notebooks.  
  In this template, every input (like *Age* or *Glucose*) is tied to a variable that flows into the database insert.  
  

- **Notebooks**  
  Notebooks are where logic lives. They can run SQL, Python, R, or Pixel code in sequential cells.  
  In this template, the notebook builds an `INSERT` query and executes it against the database.  
  

- **Database Engines**  
  To store your inputs, you need a connection to a database. SEMOSS provides database engines that can be linked to notebooks.  
  This template uses a sample **Diabetes database engine**.  
  
- **Button Actions**  
  Buttons can be wired with actions, in this case, an **OnClick** that runs the notebook and captures the result.

## The Workflow

The *Create Diabetes Record* template is designed to show how SEMOSS turns a simple form into a live data-capture application.  
It provides all the wiring viz. variables, notebooks, database actions, and response handling so you can see the moving parts in action.  

What makes this template powerful is that while it starts with a set of predefined fields (Age, Blood Pressure, Glucose, Cholesterol, etc.), you can **add, remove, or rename variables** to match your own data model. Whether your focus is clinical studies, operational metrics, or business workflows, the same pattern applies.

### Variables Flow Into the Notebook

The template includes a notebook named **insert-diabetes-record** with three key cells:

#### Table Preview (SQL)  
The first cell gives you a quick view of the diabetes table before and after your inserts:
   ```sql
   SELECT * FROM diabetes
   ```

![Notebook cell with SELECT query](/img/CreateDiabetesRecord/SelectQuery.png)

#### Database Setup (Python)
The second cell establishes a live connection to the diabetes database engine and the call looks like:
```
from gaas_gpt_database import DatabaseEngine;databaseEngine = DatabaseEngine(engine_id = "950eb187-e352-444d-ad6a-6476ed9390af", insight_id = '${i}');a = FRAME_33516.columns.to_list();a.remove("DIABETES_UNIQUE_ROW_ID");col_string = ", ".join(a);inputValues = ["{{DRUG}}","{{LOCATION}}",float({{GLYHB}}),float({{BP_1D}}),float({{BP_2D}}),float({{WAIST}}),float({{RATIO}}),float({{HEIGHT}}),"{{FRAME}}",float({{HIP}}),float({{HDL}}),float({{BP_1S}}),float({{BP_2S}}),float({{STAB_GLU}}),"{{GENDER}}",float({{ID}}),float({{TIME_PPN}}),float({{WEIGHT}}),float({{CHOL}}),float({{AGE}})];filtered_columns = [];filtered_values = [];filtered_columns, filtered_values = zip(*[(col, f"{val}") if isinstance(val, str) and val else (col, val) for col, val in zip(a, inputValues) if isinstance(val,(str,float)) and val]);filtered_columns = ", ".join(filtered_columns);filtered_values = str(filtered_values);QS = f'INSERT INTO diabetes({filtered_columns}) VALUES {filtered_values}';
```
It dynamically pulls the list of available columns, excluding the system-managed primary key `DIABETES_UNIQUE_ROW_ID`.
This ensures that only user-supplied fields are included in the insert.


![Python cell showing DatabaseEngine setup](/img/CreateDiabetesRecord/DatabaseSetup.png)


#### Insert Query (Python)
Here QS is dynamically built from your input variables. Empty values are filtered out to prevent mismatched column count


The final cell constructs and executes the insert.
All your form variables (like AGE, BP_1D, CHOL, GLYHB) are substituted into the query string QS.
```
databaseEngine.insertData(query=QS)
```

The final query may look something like:
```
INSERT INTO diabetes(DRUG, LOCATION, GLYHB, BP_1D, BP_2D, WAIST, RATIO, HEIGHT, FRAME,
                     HIP, HDL, BP_1S, BP_2S, STAB_GLU, GENDER, ID, TIME_PPN, WEIGHT,
                     CHOL, AGE)
VALUES ('Metformin', 'Mumbai', 6.5, 80, 85, 92.0, 0.92, 170.0, 'Medium', 100.0,
        45.0, 120.0, 118.0, 105.0, 'M', 12345, 90.0, 75.0, 210.0, 45.0);
```


![InsertData call and variable mapping](/img/CreateDiabetesRecord/InsertQuery.png)


Together, these three cells demonstrate the end-to-end logic: preview the table → connect to the database → run the insert query.

### "Add record" Button Replaces “Run All”

In the notebook editor, developers can run all cells at once using the **Run All** button.  
The *Create Diabetes Record* template makes this same flow available through the **Add Record** button, giving end users a straightforward way to trigger the insert.

- **OnClick Action** → runs the `insert-diabetes-record` notebook.  
- **Loading State** → linked to the `db-response` variable, so users see progress while the insert runs.  
- **Output** → the result of the insert (success or error) is shown directly in the form.


![Add Record button block settings and notebook Run All button](/img/CreateDiabetesRecord/AddRecordButton.png)

The button simply streamlines the process, making a technical operation easy to use in a day-to-day context.

---

### Viewing the Database Response

Once the **Add Record** button runs the notebook, the result is stored in the variable `db-response`.

- On success, you’ll see a confirmation message (for example: `true` or “Record inserted”).  
- On error, you may see details like *“not enough values”*, which usually means a required field was left blank.  

A text block in the template is already wired to display the value of `db-response`, so you can test the feedback loop immediately.  

![Response text block showing success or error message](/img/CreateDiabetesRecord/DbResponse.png)

### Pre-Processing and Validation

In SEMOSS, each block can be enhanced with **pre-processing logic and validation rules** that run before a record is committed to the database.

- **PreProcess Actions**  
  Automate background steps such as normalizing a value, fetching a lookup code, or preparing related data. For instance, entering a medication name could automatically retrieve its standard identifier.

- **On Change Actions**  
  Create responsive forms that adapt as users type. A classic example: once *Height* and *Weight* are entered, the system can instantly compute and display BMI — no extra clicks required.

- **Required Fields**  
  Ensure that critical details are always captured. By marking a block as required, you guarantee that a record cannot be added until essential information is provided.

Together, these features transform a simple form into a **smart, dependable workflow**: guiding users toward accuracy, reducing errors, and reinforcing confidence that every new record is both valid and complete.
